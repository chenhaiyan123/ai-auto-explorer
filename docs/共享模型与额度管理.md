# 共享模型与额度管理

2026-09-10：本机实现并完成模拟验收，尚未云端部署、未接入在线支付，未进行真实付费模型验收。

## 产品与成本边界

模型推理由 DeepSeek、智谱、Claude、OpenAI 等供应商执行，平台不需要部署这些基础模型或购买 GPU。平台仍需要后台执行模型转发、身份校验、共享密钥保管、额度记账、事实和研究记录保存以及唤醒调度。用户关闭电脑后继续研究，也依赖这个后台。

当前后台是一个常驻 Node 进程，使用持久磁盘及单进程锁。多个用户共用后台，无须每个用户购买一台服务器。若使用函数计算，需要改造调度、外部数据库、事务和并发控制；不能直接上传当前运行包替代常驻服务。

当前额度以供应商返回的输入和输出 Token 合计记录，各模型分别记账。它不是人民币余额，也不代表不同模型相同 Token 成本相同。缓存、输入和输出的供应商价格可能不同，正式定价应依据真实账单。平台共享调用由平台的供应商账户付费；用户自带 Key 的模型调用费用由用户向供应商承担，平台后台仍有自身成本。

## 使用方式

1. 运维按《云端唤醒部署》配置可信登录服务、加密主密钥、HTTPS 和持久卷；服务端设置 `WAKE_ADMIN_IDENTITIES` 为登录服务确认的完整管理员邮箱。浏览器管理员标志和前端密码不能授予此权限。
2. 管理员通过首页「管理员入口」使用已授权邮箱的验证码登录，打开右上角「管理员后台 → AI 模型与额度」，添加显示名称、协议、接口地址、模型 ID 和 API Key。优先提供 DeepSeek、通义千问、豆包、Kimi 预设；OpenAI、Claude、Gemini、Grok 和智谱保留预设且默认关闭，也支持白名单内的兼容接口。填写供应商当前支持的模型 ID，设置单次最大输出和全站该模型的 UTC 日 Token 上限，确认后启用。
3. 选择用户登录邮箱和模型，手动增加 Token，并留下分配依据或订单备注。系统只记录管理员分配，不验证实际收款；备注不能充当支付到账凭证。
4. 用户在团队的各 Agent 模型设置中选择「平台共享模型」，无需看到或填写共享 Key；也可以继续使用自己的接口和 Key。云端唤醒的通用模型或每个角色也支持共享模型。
5. 查看余额、预留额度和使用记录。修改、分配及调用后模型选择器刷新余额，跨页面操作可手动刷新。测试连接也会调用模型和消耗额度。

## 额度和失败处理

- 请求前按上下文字节数和最大输出保守预留 Token，实际返回用量后结算并释放差额。预留量不是精确 tokenizer 结果，可能使余额尚有剩余的请求被拒绝。
- 按用户和模型隔离余额；每个模型另有全站 UTC 日上限；云端还有原有的项目调用次数与全局调用次数预算。当前不支持自动周期充值或自动发放免费额度。
- 同一用户只允许一个共享请求在执行；重复请求 ID 不再次发送供应商。分配请求也支持幂等，防止重复点击多记额度。
- 超时、断网或供应商未返回用量时，不能确定是否已计费，保留预留并标记待核对。管理员应查供应商记录后填入实际 Token 数和依据，才能结算。没有自动退款或重试。
- 若实际用量超过预留，按实际记账并停用该模型，防止继续扩大差额；这不是供应商账单的绝对金额硬上限。
- 重启后未完成的调用转为待核对，保留预留；不自动重发。正在运行的调用不允许人工结算。
- 模型最多 50 个，分配记录与调用记录各最多 10,000 条；达到上限拒绝新增，避免静默丢弃账目。页面展示最近 100 条，后续需增加归档与导出管理。

## 密钥与部署

共享 Key 仅存在后台加密存储，目录、余额和记录接口不返回 Key。编辑时留空保留原 Key；更换接口目标或协议时须重新填写。供应商接口受 HTTPS 主机白名单约束，后台忽略客户端提交的供应商地址、共享 Key 或账户身份。

共享账本与凭据复用 `WAKE_MASTER_KEY` 加密，务必分别备份主密钥和持久数据卷。仅运行一个后台副本；这套文件事务不支持多个实例共享写入。

## 已完成的验收

- `npm run test:shared`：11 项服务端检查通过，包括管理员权限、未配置或暂停的模型不能调用、国内四家接口路由、密钥加密、不回显、余额隔离、幂等、日限额、并发预留、异常结算、Claude 缓存用量、云端角色配置与重启恢复。
- `npm run test:agents`、`npm run test:inquiry`：18 + 10 项原团队检查通过。`npm run test:wake`：15 项状态机与 10 项后台集成检查通过。
- 生产构建通过。本机浏览器使用真实管理组件和后台、模拟供应商响应，完成模型编辑、保留 Key、指定用户增加 12,000 Token、一次调用实际扣除 100 Token 的操作验收。
- 这些检查没有真实充值、真实供应商扣款或云端部署。接入正式 Key 后，需小预算验证供应商用量、权限隔离与部署恢复，再开放用户使用。

后续在线充值应通过服务端核验支付回调后再增加额度，记录不可重复的订单和到账状态；当前管理员手动分配接口不能替代支付系统。

## 管理后台整合与可用状态

原有用户统计和用户留言保留在同一个管理员后台。管理员登录改用已有真实邮箱验证码服务，再通过共享后台核对管理员名单；不再使用前端环境变量密码授予权限。普通邮箱登录后若后台认定是管理员，也会出现右上角入口。未部署后台或账号未授权时，不会显示可操作的管理员入口。

绿色圆点表示后台已保存 Key、管理员已开放且当日模型额度尚未耗尽；灰色表示缺少 Key、暂停或额度受限。个人 Token 余额单独显示。状态不是实时网络连通测试，保存配置也不自动产生付费调用。暂停模型和无 Key 草稿仍可在目录看到，但不能被用户选用；后端同样拒绝调用和云端角色绑定。

内置预设不自动创建凭据或开启模型。用户尚未录入实际 Key 时，国内四家也显示灰色。当前浏览器验收使用本机模拟 Key，不代表已接入真实供应商。已在浏览器验证统一后台三个选项卡、点击千问预设自动填写接口、保存模拟 Key 并开放后显示绿点，以及未配置和预留模型保持灰点。真实邮箱管理员登录与云端服务仍待部署联调。

接口配置参考供应商官方说明：[通义千问](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[Kimi](https://platform.kimi.com/docs/api/chat)、[火山方舟](https://www.volcengine.com/docs/82379/1795150)、[Gemini 兼容接口](https://ai.google.dev/gemini-api/docs/openai)、[Grok](https://docs.x.ai/developers/quickstart)。千问默认使用仍可用的北京公共域名；如切换业务空间域名，需将确切主机名加入后台白名单，并使用同地域 Key。
