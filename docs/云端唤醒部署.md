# 云端唤醒后台 · 部署与验收

这是独立于静态网站的常驻 Node 服务。首版面向**单台云服务器、单个执行器、有持久磁盘**，可部署到已有 ECS 或其他 Linux 云主机。GitHub Pages 仍托管网页。不能把这个进程直接放入请求结束就冻结的函数计算，也不能使用临时容器磁盘冒充持久存储。

目前已完成代码、构建与本机测试，尚未部署云端；已通过既有平台体验接口完成一次真实 DeepSeek 案例，详见 [发布说明](问题心跳与英文设置-发布说明.md)。现有阿里云登录函数继续负责身份验证，不承担研究调度。

## 部署

1. 在已有服务器检出本版本，安装 Docker Engine / Compose。服务需要出站 HTTPS（登录、Crossref、用户选定模型），反向代理负责公网 HTTPS。
2. 把 `server/wake.env.example` 复制为仓库根目录的 `.env.wake`。填入正式登录后端地址；在服务器本地生成 32 字节随机 `WAKE_MASTER_KEY`，保存到服务器的密钥管理环境。文件权限设为 `600`。不要把密钥放入聊天、Git、GitHub Variables 或任何 `VITE_*` 变量。
3. `docker compose -f compose.wake.yml up -d --build`。容器内由非 root 用户运行，后台只映射主机 `127.0.0.1:8790`，数据保存到命名卷 `wake-data`。**只运行一个副本**；当前文件事务不是跨主机或跨容器的分布式锁。
4. 在现有 HTTPS 反向代理绑定一个后台域名，把请求转发到 `127.0.0.1:8790`。限制请求体为 300 KB，设置请求超时至少 90 秒，保留 Authorization 和 Origin。代理不得记录请求体或 Authorization。唤醒操作不等待整轮研究完成，但共享模型的 `/shared/chat` 请求会等待单次模型结果。
5. 先检查 `https://后台域名/health`：返回 `service=hiexplore-wake`、`testMode=false`。再用实际网站登录检查未登录请求拒绝、登录请求成功、不同用户隔离。
6. 在 GitHub Actions Variables 设置公开配置 `VITE_WAKE_API=https://后台域名`，重新运行网页部署。这个变量只有地址；网站把登录凭据发送给运维配置的可信后台。页面不接受任意用户输入的后台地址。
7. 打开一个测试项目的「项目总览 → 唤醒设置」，配置后台通用模型（或分别配置全部角色），再开启云端研究。用户密钥通过 HTTPS 传输，AES-256-GCM 加密存盘；状态接口只返回模型标识。浏览器已有 API Key 不会自动上传。
8. 若提供平台共享模型，在服务端 `WAKE_ADMIN_IDENTITIES` 填入登录服务核验的管理员完整邮箱。网站「管理员后台 → AI 模型与额度」可添加供应商接口、加密保存 Key，并按用户和模型手动分配 Token。团队和云端唤醒设置均可选择「平台共享模型」。详见 [共享模型与额度管理](共享模型与额度管理.md)。

## 实际运行规则

- 项目、探索分支、问题、用户共同确定存储范围。切换分支不会复制或停止其他分支的后台；需要分别暂停。新分支默认未开启。
- 用户新线索即进入持久队列。基础检查默认 24 小时，策略复盘默认 7 天。没有新线索的检查不调用模型；连续无更新时检查间隔退避至基础值的 3 倍。离线错过的多个周期合并处理。
- 一轮通常调用项目经理、思想家或执行者、验证者、审计者，共 4 次。经理判定不值得推进可在 1 次调用后结束。默认每次唤醒最多 5 次、每天每问题最多 12 次、全服务每天最多 100 次；按 UTC 日期重置。这是调用次数和输出长度限制，不是精确人民币额度。
- 每个请求发送前先落盘预留额度；全局预算同样落盘。超时、中断、无效输出、上下文变化会停止并保留步骤日志，需用户检查后重新开启，避免自动重试可能已计费的请求。
- 每轮保存背景、角色描述、事实快照、触发线索及各步骤输出。已核验事实的新增、撤回和修订形成各角色共用的记忆差异；未经人工核验的候选发现不进入已验证记忆。云端候选可送回事实看板人工核验。
- 当前采集器只读取 Crossref DOI 元数据，不是全文检索或现实实验执行器。模型提出的实验方案仍待执行。相同来源内容去重，完全重复的候选判断不会再次计为进展；语义改写后的重复仍依赖经理和审计判断，不能承诺完全识别。
- 网站打开此问题时同步背景与事实，关闭页面后后台使用最后同步的快照。项目经理对话会读取云端进展。候选事实导入本地后由现有探索树保存；后台每次唤醒不会自动改写用户的笔记或创建本地探索阶段。
- 单范围最多 2,000 条线索与 1,000 轮研究，达上限停止并保留记录。网页显示最近 10 轮，完整状态可导出。首版尚未提供在线历史清理界面；上限后由管理员归档，不应直接删除用户记录。

## 运维与恢复

加密密钥和数据卷需分别备份，二者缺一无法恢复角色 API Key。备份时先停止执行器并等待请求结束，再对数据卷做快照。部署和回滚都复用原卷与密钥；不要运行 `docker compose down -v`。

服务日志不写入 API Key；角色请求的模型标识保存在步骤记录中。首次部署只读白名单内的 HTTPS 模型服务；接入自托管或新的模型域名需由运维确认主机名后更新白名单，不能放开到任意内网地址。

关闭研究使用项目内的「暂停云端研究」。这会阻止后续调用，已发出的请求可能仍计费。退出网页或退出账号不会发送暂停。通过网站删除项目时，会先暂停该项目的全部云端分支与问题；无法确认暂停则保留本地项目。直接清除浏览器存储不会触发这个流程。后续需要增加独立的云端项目管理和用户数据删除流程。
