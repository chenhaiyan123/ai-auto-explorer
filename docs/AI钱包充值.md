# AI 钱包充值

用户给自己的 AI 钱包充人民币；AI 在**平台共享模型**上干活、额度不够时，按模型定价自动从余额兑换 Token。

## 怎么开

在云端服务器（pay.hiexplore.com）的环境变量里：

| 变量 | 作用 |
|---|---|
| `BILLING_SALES_ENABLED=true` | 支付总开关（已有） |
| `BILLING_TOPUP_ENABLED=true` | **充值开关**，不设就是关的，前端显示「暂未开放，不会扣款」 |
| `BILLING_ALLOWED_IDENTITIES` | 验收期只让这几个邮箱能付款（已有，建议先只放自己） |

然后重新部署：`docker compose -f compose.wake.yml up -d --build`。

最后在「模型管理与额度分配」里，给要开放的共享模型填 **AI 钱包兑换价（元 / 百万 Token）**。0 = 这个模型不能用钱包余额。

## 规则

- 档位固定 ¥10 / ¥30 / ¥100 / ¥300（`shared/billing-plans.json` 的 `topup.amounts`，单位分）。金额只认后端，前端传别的金额会被拒。
- 到账以支付渠道验签 / 查单为准，重复回调、重复查单只加一次钱。
- 自动兑换：额度不够这次请求的预留时，扣 `max(¥1, 差额 × 价格)`，换成该模型的 Token；兑换的 Token 用不完留着下次用。
- 先扣钱再加额度；加额度失败自动退回钱包（流水里有「兑换失败退回」）。
- 钱包有钱但不够一次兑换：直接报「AI 钱包余额不足，请先充值」，不透支。
- 用户自己的 API Key 调用不碰钱包。
- 流水在 `/billing/account` 的 `wallet.tx`；管理员在 `/admin/billing` 的 totals 里看到全站余额 `walletBalance` 和已兑换 `walletSpent`。

## 还没做

- 提现 / 退款：目前要人工处理（文案写的是「需要退款请联系客服」）。
- 服务广场订单从钱包付款。
- iOS 不开放充值。

## 服务广场用钱包结算（2026-10-21 追加）

- 下单 / 选中接单方案时可选「用 AI 钱包担保付款」：钱从买方钱包扣出、平台暂存；
  买方验收 → 打进卖方钱包（流水「接单收入」）；卖方拒单 / 取消、或买方在对方接单前取消 → 全额退回。
- 卖方接单后买方不能单方面取消；交付后 7 天买方不验收，自动完成放款。有争议人工处理。
- **收入只能在平台内花（兑换模型额度、买别的服务），不能提现。** 平台替双方收付现金需要支付牌照，开放提现前先确定合规方案。
- 平台抽成：`MARKET_FEE_BPS`（万分比，默认 0）。管理员 `/admin/billing` 的 totals 里有 `walletEscrow`（平台暂存中）。

## AI 项目经理

- 每个项目一个「AI 授权」（服务广场 Agent 令牌，只存在用户浏览器里），权限和额度来自项目的花钱权限：
  单笔上限 = 花钱权限单笔；总额度 = 每月上限（没填就是单笔 × 10）。**后端按令牌卡额度**，不靠前端自觉。改权限自动换令牌。
- 买：某一步卡在 AI 做不了的事 → 有价格在权限内的现成服务就用钱包担保下单；没有就发布需求（预算 = 单笔上限）。钱包不够就撤单并在对话里提示充值。
- 卖：项目钱包页打开「允许 AI 接单」→ AI 只挑纯 AI 能做完的需求（调研、整理、写作、分析）报价；中标后自己做完、交付（文字交付），对方验收后钱进钱包。项目醒来时每 6 小时最多自动接一轮，也可以点「现在去接单看看」。
- 模型：钱包页列出平台模型的价格和余额，可「设为默认」「充 ¥10 / ¥30 到这个模型」「让 AI 自己挑（最省钱）」；AI 团队每个角色也能单独选模型。

## 线上验证清单（服务器部署后）

1. `/billing/catalog` 里 `topupEnabled: true`。目前线上：微信支付可用、支付宝未就绪。
2. 用自己的账号充 ¥10 → 钱包页余额变化、流水有「充值」。
3. 后台给一个模型填兑换价 → 钱包页「充 ¥10」→ 模型额度增加。
4. 两个账号：A 上架 ¥1 的服务，B 用钱包担保下单 → A 接单、交付 → B 验收 → A 钱包 +¥1。
