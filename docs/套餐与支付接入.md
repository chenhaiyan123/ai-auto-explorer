# Free / Pro 套餐与支付接入

2026-09-15。本机实现；微信真实商户的证书签名、API v3 密钥解密、平台响应验签已通过。尚未上线收款、未验证真实付款。

## 页面入口与当前范围

- 顶栏「收费与套餐」，以及「设置 → 收费与套餐」使用同一张 Free / Pro 对比表；中文和英文均有文案。
- Free 免费；Pro 69 元 / 日历月，手动续费，不自动扣款。成果包 3.99 元 / 固定版本。
- 旧的 19.9 元弹窗及点击即写 localStorage 开通逻辑已移除；旧本机会员标记不能赋予付费权限。
- 原有笔记、原始资料和基础文本导出保持免费。研究报告弹窗新增「导出成果包」：明确确认上传报告后保存不可变版本，按服务器权限下载 ZIP，包含 HTML（可打印为 PDF）、Markdown、JSON 记录与说明。
- 「收费与套餐」可查看订单、恢复核对付款、下载已解锁成果。Pro 有效期内下载的版本永久解锁，到期不影响同版本重复下载。
- 管理员后台新增「支付订单」，仅显示核验后的订单与累计收款（非扣除退款、手续费后的净收入）。

## 尚未实现的权益

3 / 10 个长期问题的套餐限制、10 / 100 次月度研究额度、每周 / 每天观察、共享模型周期额度发放尚未接入。现有共享模型 Token 账本与唤醒预算仍独立生效。页面明确标注待启用；不承诺无限计算或已经云端常驻。

因此 `BILLING_PRO_ENABLED` 必须保持 false，直到上述权益交付接入并验收。`BILLING_SALES_ENABLED` 默认也为 false。不得仅为了显示绿灯而开启售卖。

## 支付渠道

首版完整流程为支付宝「电脑网站支付」，适合在官网上跳转支付宝官方收银台并扫码支付。采用官方 RSA2 协议与 Node 内置密码学实现，无新增 npm 依赖；只支持直连商户普通公钥模式（PEM），不支持服务商代收、证书模式、手机网站 / App 原生支付。

微信 Native 支付已完成本机实现：普通企业商户、平台证书模式；浏览器使用 qrcode 本地生成订单二维码，不向第三方二维码服务传输订单。收费页可选支付渠道，成果包支持微信购买。尚未完成公网部署与真实支付验收，因此保持灰色入口和关闭售卖。H5 / JSAPI 暂未接入。

微信请求使用商户证书 RSA 签名；返回消息与回调先验签，通知再通过 API v3 密钥做 AES-GCM 认证解密，核对商户号、AppID、NATIVE 类型、订单号、交易号、金额与币种，仅 SUCCESS 授权。主动查询用于回调丢失补偿。平台证书首次用认证解密引导并复验完整响应签名，业务请求按需每 6 小时刷新，未知证书序列号触发限频刷新。没有后台定时下载任务；无支付活动时不发请求，下次活动恢复时刷新。

订单在调用微信前先写入持久账本；远端请求超时、重复点击及重启复用同一个订单号。并发准备同一订单只调用一次下单；有效回调的到账和权益交付仍在同一账本事务完成。

订单以服务器固定金额（6900 / 399 分）创建，真实身份来自现有登录服务。客户端金额、用户标识及支付成功声明不参与到账处理。支付宝同步返回页不授予权益。

异步通知校验 RSA2 签名、app_id、seller_id、商户订单号、金额、支付状态；有效通知以同一加密账本事务记录到账和授予权益。重复通知不重复延期；交易号不能跨订单复用。用户主动查单会验签原始响应，并校验查询订单与返回订单一致；同一订单至少间隔 10 秒查询一次。

未付款订单有效期 15 分钟。页面过期不等于已完成支付宝关单；如已经付款必须刷新核对。迟到的有效付款回调仍会被处理。关闭页面不取消订单，不会自动退款。

## 商户与服务器配置

需要：已开通电脑网站支付的支付宝商家应用、应用 App ID、对应卖家 seller_id、应用私钥 PEM、支付宝公钥 PEM，以及可被支付宝访问的 HTTPS 支付后台。个人收款二维码不能替代订单回调接口。

密钥在服务器上配置文件路径，不放进网页、Git、`VITE_*`、聊天或客户端缓存。环境变量示例见 `server/wake.env.example`：

```dotenv
BILLING_SALES_ENABLED=false
BILLING_PRO_ENABLED=false
BILLING_ALLOWED_IDENTITIES=
BILLING_PUBLIC_URL=https://你的支付后台域名
ALIPAY_APP_ID=商家应用ID
ALIPAY_SELLER_ID=卖家ID
ALIPAY_PRIVATE_KEY_FILE=/run/secrets/alipay-private.pem
ALIPAY_PUBLIC_KEY_FILE=/run/secrets/alipay-public.pem
```

真实小额验收时，把 `BILLING_ALLOWED_IDENTITIES` 配置为获准测试的真实登录邮箱（多个邮箱用逗号分隔），再开启 `BILLING_SALES_ENABLED`。服务器按登录服务核验的身份强制限制新下单，管理员身份不自动绕过此名单。公开目录只返回是否处于限量验收，个人账户只返回能否购买，不返回其他邮箱。前端向未获准账号显示暂不能购买；名单收紧不影响旧订单到账、查单及已解锁成果下载。清空名单会恢复面向所有已登录账号的购买范围，因此仅在收款、交付和退款处理验收后清空。

付款回调：`POST /billing/notify/alipay`。支付宝网关固定为官方 HTTPS 地址，不能从浏览器提交替代地址。前端 `VITE_BILLING_API` 留空时复用 `VITE_WAKE_API`。

微信配置见 `server/wake.env.example` 的 `WECHAT_*` 字段；回调为 `POST /billing/notify/wechat`，成功持久化后返回 HTTP 204。证书目录需服务用户可写以保存轮换后的平台证书；私钥、API v3 密钥以文件路径配置，均放在前端目录和代码仓库之外。初始化下载命令：

```sh
node --env-file=.env.wechat.local server/wechat-certificates.mjs /安全目录/platform-certificates
```

上述 `.env.wechat.local` 是本机准备文件，不会被线上服务自动读取；部署时须合并至服务端环境并将文件路径改为容器挂载路径。当前 `BILLING_PUBLIC_URL` 为空，Native 适配器不会激活。已有静态官网和登录 FC 不等同于具备持久账本的支付后台。

复用现有后台真实邮箱登录、管理员名单、加密主密钥和单进程持久盘锁。部署镜像已包含支付代码与共享价格表。该文件事务架构不支持多副本；必须持久化数据卷和主密钥，不可直接部署为无状态函数。账本容量有限，达到上限拒绝新订单 / 成果，不删除历史账目。

开放顺序：商户签约 → 部署持久后台与 HTTPS 回调 → 核对服务条款、交付和退款流程 → 经商户授权的小额真实支付与重复回调 / 丢失回调验收 → 才开启成果包售卖。Pro 在套餐权益验收前继续关闭。当前没有自动退款接口和权益撤销管理；正式售卖前还需完成退款对账与处理路径，不能依靠修改加密文件处理退款。

## 测试与限制

`npm run test:billing` 使用临时测试 RSA 密钥、模拟支付宝响应和本机临时端口；不连接支付平台、不产生真实付款。覆盖关闭支付、认证 / 管理员隔离、金额篡改、并发幂等、验签错误、商户不匹配、重复通知、重启恢复、主动查单、成果版本、会员到期和日历月续费。

前端测试覆盖价格表、关闭购买、收银台 URL 白名单、HTML 转义与 ZIP 导出。现有后台和共享模型回归也须通过。

本次结果：生产构建通过；支付宝支付 9 项、微信支付 5 项、共享模型 11 项、唤醒后台 11 项，均通过；前端静态渲染、二维码生成和导出安全检查通过。微信新增测试覆盖证书认证解密、原文验签、非法签名、过期通知、错误商户、密文篡改、网络超时后订单恢复、幂等解锁、HTTP 回调与查单补偿。测试使用临时自签名证书和模拟平台，不产生真实订单。另有一次真实官方平台证书下载与解密验签通过；这不能替代 Native 付款验收。

视觉验收尚未完成。二维码依赖及类型定义此次经审批安装成功，支付宝协议仍使用 Node 内置能力；商户后台 Computer Use 访问被工具禁止，商户设置由用户手动完成。
