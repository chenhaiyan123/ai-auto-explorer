## 二、要你手动配的三件事（约 20 分钟）

### 1. Umami 流量统计（必做，目前完全没有）

`VITE_UMAMI_WEBSITE_ID` 现在是空的，所以站点**零统计**。

1. 注册 https://cloud.umami.is （免费额度够用，无 cookie、不用弹隐私提示）
2. 添加网站，域名填 `www.hiexplore.com`，拿到 Website ID
3. 填到 GitHub 仓库 → Settings → Secrets and variables → Actions → **Variables**：
   - `VITE_UMAMI_WEBSITE_ID` = 那串 ID
4. push 一次触发重新构建

> CSP 已放行 `https://cloud.umami.is`，不用改代码。

### 2. 反馈收件邮箱（必做）

去阿里云 FC 控制台，`hiexplore-auth` 函数的环境变量里加：

- `FEEDBACK_TO` = 你想收反馈的邮箱（建议专门用一个，别和登录验证码混在一起）
- `FEEDBACK_PER_DAY` = `5`（可不填，默认 5）

**不配也不会坏**：端点返回 503，前端自动降级成预填好的 GitHub Issue 链接。但那样你只能收到愿意注册 GitHub 的那一小撮人的反馈，国内用户基本会流失掉。

> 复用的是 FC 里已有的 `RESEND_API_KEY`，不用新开任何服务。反馈直接投到邮箱——邮箱本身就是持久化，绕开了 FC 内存态冷启动丢数据的问题。

### 3. 确认 Tawk 聊天挂件线上生效

`VITE_TAWK_PROPERTY_ID` 本地 `.env.local` 配了，但**线上取的是 GitHub Variables**。去仓库 Variables 里确认 `VITE_TAWK_PROPERTY_ID` 也配了，没配就补上。

## 三、漏斗指标定义

埋点已经按这条链路铺好，Umami 里建一个 funnel 就能看：

```
访问首页
  ↓  trial_start          点了「先免注册体验」
  ↓  project_created      建了第一个项目 ← 真正的「上手」分界线
  ↓  team_built           用了 AI 组队
  ↓  auto_explore_start   让团队自动跑起来
  ↓  vault_exported       导出了成果 ← 最强留存信号
```

旁路信号：

| 事件 | 说明 | 该怎么用 |
|---|---|---|
| `trial_quota_exhausted` | 体验额度用尽 | 有人触顶＝产品有吸引力，考虑提额；一直是 0＝根本没人用到那一步，问题在更前面 |
| `feedback_open` / `feedback_submitted` | 反馈按钮打开数 / 实际提交数 | 两者差距大＝反馈表单太麻烦或用户没话说 |
| `feedback_failed` | 提交失败 | 大于 0 说明 `FEEDBACK_TO` 没配或 FC 挂了 |
| `login` | 邮箱登录 | 和 `trial_start` 比，看有多少人愿意从游客转正 |
| `record_decision` / `fork_decision` | 决策功能使用 | 这是你的差异化功能，没人用就说明入口太深或价值没讲清 |

**第一轮推广只看三个数就够**：进站人数、`project_created` 转化率、反馈条数。其他先别管，样本量不够看了会误导。

## 五、怎么把反馈变成真的对话

收到反馈只是开始，关键是回。几条经验：

1. **24 小时内回**，哪怕只是「收到了，这两天看」。留了联系方式的人期待被回应，晾三天就再也不会提第二条。
2. **修好了要回头告诉他**。「你上次说的那个卡住的地方，今天修了」——这句话的转化率高于任何推广文案，这个人很可能变成帮你传播的人。
3. **「没看懂」比「有报错」更值钱**。报错是代码问题，好修；没看懂是产品问题，说明你的心智模型没传达出去——而你自己永远发现不了这个，因为你太熟了。反馈弹窗把「😕 没看懂」放在默认选中位置就是为了这个。
4. **别辩解**。用户说「这个功能很鸡肋」，先问「你当时想做什么」，而不是解释它为什么有用。
