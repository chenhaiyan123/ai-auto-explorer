# 长期关注与重要事件邮件

## 用户流程

在项目总览点击「让它替我持续关注」，选择一个已开放的云端模型、资料来源，并决定是否订阅邮件。该操作明确将后台团队统一绑定到所选模型；需保留角色独立模型时使用高级设置。自带 API Key 仍通过原有高级配置流程授权保存。

开启在服务端完成：校验身份、项目范围、模型和额度，再保存问题、后台模型与调度计划。重复点击不会重复领取额度或创建首次事件。启动失败不会显示已开启。后台按日检查、每周复盘，默认每日最多 8 次模型调用、每次唤醒最多 4 次，单次输出上限 1024 Token；这只是调用上限，不保证免费额度能覆盖完整轮次。

来源分为用户提交的资料/实验结果、Crossref 论文元数据。只有后者有自动外部采集。不会声称自动访问任意网站、读取全文或操作实验设备。安静时降低检查频率。

首轮经理保存可证伪假设、证据缺口、下一步和停止条件。项目总览展示最近实际检查、下次检查与观察来源；回访时通过「原判断—新依据—核验—当前判断—下一步」查看变化。AI 提议仍标记待审核；证据被撤回则显式提示重新核验。

## 体验成本

`WAKE_STARTER_TOKENS` 和 `WAKE_STARTER_POOL_TOKENS` 控制一次性体验额度。默认均为 0。

开启时，只有从未获分配共享模型额度且从未领取过的账户可领取一次；跨模型、跨项目和并发不会重复领取，额度池持久化。此功能不会自动收款。个人、模型日额度和全站日调用限制仍生效。无需为了赠送额度重置账本，也不要删除 starter 记录。

建议小规模试用配置为每账号 30,000 Token、全站累计 300,000 Token；不改变现有每天 40 次调用的总保护。扩大前由管理员根据实际用量调整。

## 发信与退订

- 复用验证码服务使用的 Resend 密钥及 `MAIL_FROM`，配置在研究后台 `.env.wake`。
- 必须设置可信 HTTPS `WAKE_PUBLIC_URL` 和 `WAKE_APP_URL`。发信能力返回前端；未配置时订阅入口不可用，不假装已发送。
- 收件人从服务端认证身份获取，仅使用登录邮箱。客户端不能指定其他收件人。
- 默认不订阅。每个问题分别选择；安静模式停发邮件，研究本身不因此停止。
- 仅发送新产生且仍相关的待办、引用当前已核验事实的判断变化，以及运行受阻。不发送普通检查次数、无依据的假设或订阅之前的历史事件。
- 按账号跨项目至少间隔 12 小时、滚动 24 小时最多 2 封；全站最多 50 个新邮件任务/24 小时。每封合并至多 5 条变化。
- 邮件里的退订链接 GET 只显示确认页，POST 才关闭订阅，避免邮箱安全扫描自动退订。退订不影响研究。
- 收件人、随机退订令牌、待发正文、去重记录加密持久化。发信前先持久化任务，再调用供应商。
- 网络不确定时只用同一个幂等键和固定正文重试，最多 3 次且最多 20 小时。Resend 的幂等窗口为 24 小时，过期不盲目补发，防止重复提醒。官方依据：[Resend idempotency keys](https://resend.com/changelog/idempotency-keys)。
- 供应商接受不等于邮箱已送达；页面使用「最近提交邮件服务」，不伪称用户已收到。邮件发送失败保留站内记录。

## 验证与运维

- `npm run test:life`：邮件去重、重启、限频、超时、退订、静默、失效事实、收件人约束，以及回访 UI。
- `npm run test:wake`：研究执行、首次开启、重试、预算、计划与检查时间。
- `npm run test:shared`：模型权限、令牌结算、一次性额度池及并发。
- 发布前对加密支付/模型账本做一致性备份。后端单进程，不允许另一进程同时写入同一数据目录。
- 邮件验收用明确标记的测试提醒，不把演示数据描述成真实研究结果；不要自动给体验者打开订阅。
