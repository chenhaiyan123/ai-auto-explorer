# 移动端 App：打包与上架

HiExplore 手机 App 叫「现实反馈」。它**不是 HiExplore 的移动版**——探索仍然只在电脑/云端跑
（手机后台会被系统挂起，长时探索在手机上不成立）。手机只解决一件事：
**电脑上那条探索卡在哪个现实问题上，当场给答案。**

技术上是 Capacitor 把 `dist/` 打进原生壳。用户拿到的是真正的 `.apk` / App Store 应用：
应用商店能下载、桌面有图标、能收原生推送、**能直连局域网 IoT 设备**（托管版是 https 页面，
被浏览器混合内容拦截连不上 `http://192.168.x.x`，原生壳没这个限制——这是 App 相对网页最实的增量）。

---

## 一、第一次生成原生工程

```bash
npm install                      # 会装上 @capacitor/* 依赖
npx cap add android              # 生成 android/ 目录
npx cap add ios                  # 生成 ios/ 目录（需要 macOS）
npm run mobile:sync              # build + 把 dist 同步进原生工程
```

`android/` 和 `ios/` 已加进 `.gitignore`——它们是可再生成的，而且很大。
如果以后要用 CI 出包，再把 `android/` 提交进来（但 keystore 永远不要提交）。

### 必做的一步：允许明文 HTTP

App 要能连用户实验室里 `http://192.168.x.x` 的设备，Android 9+ 默认禁止明文 HTTP。
`npx cap add android` 之后，编辑
`android/app/src/main/res/xml/network_security_config.xml`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
  <!-- 用户自己的实验设备通常是局域网明文 HTTP，必须放行；
       其余域名保持默认的"只允许 https" -->
  <domain-config cleartextTrafficPermitted="true">
    <domain includeSubdomains="true">192.168.0.0</domain>
    <domain includeSubdomains="true">10.0.0.0</domain>
    <domain includeSubdomains="true">localhost</domain>
  </domain-config>
</network-security-config>
```

> 更省事的做法是在 `AndroidManifest.xml` 的 `<application>` 上加
> `android:usesCleartextTraffic="true"` 全局放行——但那样所有域名都能走明文，
> 上架审核时可能被问，按需选择。

## 二、出一个能装的 Android 包（今天就能做）

### 调试包（不用签名，直接发给人装）

```bash
npm run mobile:apk
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

装之前手机要打开「允许安装未知来源应用」。这个包**只适合内测**，
不能上应用商店，也会被部分手机厂商拦。

### 正式签名包（能上架、能长期分发）

```bash
# 1) 生成签名密钥（只做一次，keystore 和密码务必备份，丢了就没法发新版本）
keytool -genkey -v -keystore hiexplore.keystore -alias hiexplore \
  -keyalg RSA -keysize 2048 -validity 10000

# 2) 在 android/ 里配置签名（android/key.properties，不要提交）
#    storeFile=../../hiexplore.keystore
#    storePassword=...
#    keyAlias=hiexplore
#    keyPassword=...

# 3) 出包
cd android && ./gradlew assembleRelease      # APK
cd android && ./gradlew bundleRelease        # AAB（Google Play 要这个）
```

## 三、iOS

需要 **macOS + Xcode + Apple 开发者账号（$99/年）**，没有账号连真机调试都做不了。

```bash
npm run mobile:ios      # 打开 Xcode
```

然后在 Xcode 里配 Signing & Capabilities（选你的开发者团队）→ Archive → 上传 App Store Connect。
分发只有两条路：TestFlight（内测，最多 10000 人）或 App Store 正式上架，都要过审。

## 四、上架现实清单（中国大陆）

| 渠道 | 硬性要求 |
| --- | --- |
| 直接发 APK 下载 | 无。官网挂个下载链接即可，最快 |
| 华为 / 小米 / OPPO / vivo / 应用宝 | **软件著作权证书**（自己申请约 30 个工作日，加急可缩短）+ 企业资质 |
| Google Play | 开发者账号 $25（一次性）+ 隐私政策页面 |
| App Store 中国区 | 开发者账号 $99/年 + **ICP 备案号**（已有：粤ICP备2023000583号-1） |

**建议路径**：先直接发 APK 验证有没有人真的用；确认有人用了再去申请软著和上架，
不然软著等一个月、审核再等一周，很可能是在给一个没人要的东西排队。

## 五、推送通知（还没做）

`services/native.ts` 里的 `registerPush()` 只做到"拿到设备 token"就停了，
**现在调用它会返回 null，不会假装成功**。真正跑通还差三样：

1. **Android**：Firebase 项目 + `google-services.json`。
   国内没有 Google 服务的手机收不到 FCM，需要接厂商通道（华为 HMS / 小米 / 魅族）或用极光、个推。
2. **iOS**：Apple 开发者账号 + APNs 证书。
3. **服务端**：存设备 token，在路标转成「等现实」时推一条。
   注意 `server/auth-fc.mjs` 是 FC 内存态，token 必须存到别处（这是目前唯一真正需要持久化的数据）。

在此之前，App 靠**图标角标 + 打开即见**兜着：角标数就是待办数，锁屏也能看到。

## 六、发版时容易忘的事

- 改了前端代码后必须 `npm run mobile:sync`，否则原生壳里还是旧的 `dist`。
- `VITE_AUTH_API` 在**构建时**写死进包里。给用户的包必须用生产地址构建，
  不能拿本地 `.env.local` 的地址打包。
- 版本号：Android 改 `android/app/build.gradle` 的 `versionCode`/`versionName`；
  iOS 在 Xcode 里改。`package.json` 的 version 不会自动同步过去。
- 图标和启动图：`public/icon-192.png`、`public/icon-512.png` 目前还没有，
  生成原生工程前先补上，否则用的是默认占位图。
