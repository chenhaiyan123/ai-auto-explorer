# 问题团队与事实看板

点击笔记树中的项目名称，进入该项目的「项目总览」。项目下有「项目总览」「AI 团队」「事实看板」「决策与探索分支」四个入口。展开一个想法，也能进入它自己的项目总览、团队、事实看板和正文笔记。

项目总览汇总所有想法的笔记进度、团队轮次、可信事实、待审核事项和研究发现；想法总览只汇总该想法及其后续笔记。点击卡片进入对应面板，点击笔记查看正文。团队和事实页固定归属当前问题，切换想法不会混用记录。

## 决策与探索分支

「决策与探索分支」是项目内的探索历史树。记录项目决策时，保存当时的完整项目快照，包括笔记、团队成果、事实与审核记录、研究卡片、研究发现和路线。每完成一轮团队探究也会自动保存阶段，此外可以手动命名并保存阶段。

选择历史阶段，可预览当时的决策、笔记和事实，点击「返回此阶段并新建分支」继续探索。离开当前分支前会自动保存尚未留存的进展，原分支仍完整保留；通过分支选择器可以随时切回。运行中的任务需要先暂停并等待当前步骤结束，才能切换或恢复阶段。

这是应用内的项目状态树，不是源代码 Git 工作树。旧版本的决策只有局部节点快照，会显示「仅有节点快照」，仍可创建节点分支；升级之后保存的阶段才能恢复完整项目状态。

## 团队流程

1. 在项目的「AI 团队 → 团队配置」为各角色选择模型、填写 API Key；未配置的角色跟随全局设置。
2. 首次开始时 AI 自动补齐未填写的角色描述，之后可编辑。思想家提出 3–6 个竞争假设，每个假设必须说明证伪条件。
3. 每个假设依次交给执行者、验证者和审计者。验证者收到执行成果，审计者收到执行与验证双方的成果；前置步骤失败时停止后续任务。
4. 展开任务查看完整成果、审核意见和该步骤读取的事实快照。
5. 可以在当前步骤结束后暂停，或从失败步骤重试。已完成任务和候选事实不会重复生成。刷新后，未完成轮次恢复为可继续的暂停状态。
6. 本轮结束后点击「开始下一轮探究」，思想家会收到最新事实看板及前两轮的假设和审计意见。全部历史仍保存在界面中。

每轮包含 10–19 次模型调用，接口失败可能重试。思想家、执行者、验证者、审计者分别调用自己的模型配置；第五个角色 AI 项目经理负责沟通与协调，不占用假设流水线中的步骤。不同模型的共识也不等于现实证据。执行者目前执行材料分析、计算推理和方案生成；不会调用浏览器、Shell 或实验设备，也不会把实验计划标成已完成的现实实验。应用需要保持打开，关闭后不会在后台继续调用模型。

切换侧栏、文章或项目不会改变正在运行任务的归属。登出或组件卸载后，未返回请求的结果不会写入其他用户的数据；已发出的模型请求可能仍在服务端运行。

## 事实审核

- **待验证**：人工录入或 AI 提出的候选。模型声称有来源、多个角色意见一致，都不会自动确认。
- **已确认**：人工核对原始资料后填写来源、证据摘录、适用范围和审核理由。其他 agent 可以在限定范围内引用。
- **有争议**：保留记录并明确标记不能作为可信前提。适合出现冲突、样本问题或资料过时的情况。
- **已驳回**：不再进入共享事实上下文，原记录和审核历史仍保留。

支持按状态筛选与全文搜索陈述、来源、适用范围。来源可以是 HTTP(S) 链接、文档与页码或实验记录编号。已确认记录需要先标记争议或退回，才能修订证据；修改陈述时新增一条事实并在旧记录中解释替代关系。

事实审核记录保留每次人工审核时的证据版本。任务快照保留当时已确认和有争议的记录，后续阶段会看到事实版本是否变化。记录超出上下文预算时会明确提示遗漏，不会把截断的证据链假装成完整证据。

团队探究、常规节点探究、研究模式、节点对话与团队群聊都会读取适用的问题事实看板。普通探究/对话在文章尚无独立看板时使用核心问题看板；文章创建独立看板后使用自己的记录。

## 数据与兼容性

团队数据位于 `Project.inquiries[questionId]`，`root` 表示项目核心问题，其余键为文章节点 ID。探索历史位于 `Project.worktree`，每个阶段保存一份不包含历史树本身的项目快照，分支之间不共享可变事实对象。沿用项目的 IndexedDB 持久化及 localStorage 兜底，无需新增数据库服务。旧项目首次加载时初始化当前状态的阶段，不会凭空补出此前的历史；原有 `agentTeamState` 数据不删除，新流程使用独立结构。笔记树中的旧「拆解方向」功能继续保留。

当前没有加入服务器守护进程、跨设备同步或 Markdown Vault 导出。请不要把清除浏览器站点数据当作备份操作。

## AI 项目经理

项目「项目总览」顶部和核心问题的「AI 团队」页提供项目经理对话。经理汇总本项目各想法的团队进度、最新结果、失败原因和已核验事实，帮助澄清目标、证据缺口和最小验证方案。每次对话使用经理自己的模型和角色描述；首次对话前自动起草尚未填写的描述。

经理可以给出「开始 / 继续团队」或「当前步骤后暂停」建议。点击「执行此建议」后，调用指定问题的真实团队流程。执行前检查问题归属、重复操作及状态变化，失败会显示原因。对于已完成的轮次，没有新增已核验事实或背景材料时，经理入口拒绝重复启动；团队页仍允许用户主动重新分析。旧轮次没有材料基线时允许建立一次新基线。这不是后台自动调度，经理也不会自行联网收集资料。

团队运行时可以继续与经理沟通。经理对话保存于项目核心问题 `managerMessages`，随探索阶段一同保存、恢复；它属于沟通记录，不会自动变成事实记忆。回到旧阶段时，旧回复应结合当前事实重新询问。模型请求期间阻止阶段切换；暂停项目会丢弃尚未返回的经理回复，但已发送请求可能仍在服务商运行。

## 自定义模型与角色

每个问题都有五个角色的配置：AI 项目经理、思想家、执行者、验证者、审计者。云端预设自动填写 API 地址和模型 ID：DeepSeek、Claude、OpenAI、Gemini。用户填入自己的 API Key 后可测试连接；模型 ID 和地址均可改。Ollama、LM Studio 预设填写本地服务地址，用户还需启动服务并填写已安装模型 ID。其他服务使用「自定义兼容 API」，支持 OpenAI Chat Completions 兼容协议；Claude 使用原生 Messages 协议。模型需要支持文本任务及所要求的 JSON 输出，不能保证所有厂商和所有模型都兼容。

预设按 2026-09-08 官方文档核对：

- [OpenAI Chat Completions](https://developers.openai.com/api/reference/typescript/resources/chat/subresources/completions/methods/create) 与 [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)
- [Claude Messages](https://platform.claude.com/docs/en/api/http/messages/create)
- [DeepSeek 接口](https://api-docs.deepseek.com/) 与 [思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)：有界 JSON 请求的 V4 预设使用非思考模式，为正文保留输出额度。
- [Gemini OpenAI 兼容接口](https://ai.google.dev/gemini-api/docs/openai)
- [Ollama](https://docs.ollama.com/api/openai-compatibility) 与 [LM Studio](https://lmstudio.ai/docs/developer/openai-compat)

浏览器直连取决于服务商跨域策略；受限时填写支持浏览器访问的代理地址。ChatGPT 订阅不等于 OpenAI API 密钥。预设模型的可用性取决于服务商和账户权限，用户可填写自己已开通的模型。连接测试发送一条简短请求，会使用该服务商的额度。

AI 描述依据研究问题生成，用户可编辑名称、职责或重新起草单个角色。每轮开始冻结所用描述和模型配置，任务保留实际使用的快照；后续修改默认用于新轮次。暂停或失败时可显式将已保存配置应用到未完成步骤，修改前后留痕，已经完成的步骤不重跑。经理的新配置在下次对话生效。

密钥独立保存在当前浏览器 localStorage，以账号、协议和服务地址绑定。项目数据和探索快照只含密钥引用，不包含密钥正文；更换设备需重新填写。当前没有服务端密钥托管或系统钥匙串加密，解除绑定不删除其他历史阶段可能引用的旧凭据。地址或协议变化后必须重新填写密钥。模型调用错误会去除服务商直接回显的密钥文本。

## 每轮记忆变化

每个角色都有事实记忆及变更历史。只有已人工核验且来源、证据摘录、适用范围齐全的事实可以进入记忆，保存原陈述，不让模型自行扩写结论。事实确认立即同步；出现争议、驳回或撤回时，移出当前有效记忆，并保留此前内容和原因。

每轮完成均记录一次该角色的记忆状态，包括新增、修订、撤回，或者明确「本轮无变化」。只有内容实际改变才递增版本。界面可查看前后内容、来源、适用范围和依据 ID，并跳转事实看板复核。对话中提到的新发现仍需录入并核验，不能直接写入事实记忆。

独立 Agent 测试页：`http://127.0.0.1:3000/__test__/agents.html`。使用模拟模型和合成证据，验证经理对话、操作建议、五角色配置、逐轮记忆及刷新恢复；「测试连接」按钮使用真实接口，应填写自己的有效密钥后再点击。自动化测试中的 HTTP 请求使用 mock fetch，未验证用户付费服务的连通性。


## 统一项目总览（2026-09-08）

项目原来的研究仪表盘、总览和 README 已合并为一个「项目总览」入口。目标与范围吸收旧 README 的完整内容，可直接编辑；研究摘要沿用原总览正文，可编辑并接管，接管后 AI 不自动覆盖。实时卡片、事实依据、审计、研究路线和笔记导航集中展示。项目经理对话默认收起，避免遮挡全貌。各想法对应「想法总览」。

首次加载时无损迁移：保留合并前 README 和总览的完整节点副本，在「合并前的笔记原文」中查看。旧节点 ID 和依赖关系不变，打开旧说明笔记或双链会进入统一总览。新项目不再创建独立 README。用户目标存于 `Project.overviewBrief`，不会被自动摘要覆盖，团队与经理均读取最新内容；Markdown 导出也包含更新后的目标。

目标、摘要与原文归档随探索阶段保存、恢复，合并不删除此前的探索历史。
