# 证据驱动探索：现状评估与下一步

评估日期：2026-09-08。结论：优先建设可等待、可唤醒、可追踪证据变化的探索机制，再用固定评估题决定是否升级模型。当前没有完成真实模型对比，不能判断哪种模型最适合。

## 本次实际做了什么

测试问题：**让用户读完文章后写下一个具体问题，相比仅收藏文章，是否提高七天后的回访比例？**

1. 新建独立评估页，调用项目已有模型接入层。页面配置显示 `deepseek-chat`、`trial`。首个请求报 `Failed to fetch`，思想家没有返回结果，因此真实模型测试停在第一步。
2. 代理域名在放开终端网络限制后可访问，但探测路径返回 HTTP 404；响应允许的来源显示为线上站点。这不能证明模型接口宕机，也不能单凭该响应确认浏览器失败原因；需要继续核对本地 Origin 的预检响应。守护进程配置的本地 `qwen3.5:35b` 服务端口 11434 当前未连通。
3. 使用**预设 JSON 输出**运行真实 `runInquiry` 调度代码两轮。该测试检验程序是否会继续调度，不能检验模型推理质量，20 次为本地模型回调次数，没有产生 20 次外部 API 调用。

两轮输入都没有外部证据，预设思想家每轮提出相同三个假设，执行者不产生候选事实，所有验证与审计均返回 `uncertain`。

| 检查项 | 当前实测结果 | 意义 |
| --- | --- | --- |
| 没有新增证据能否开启第二轮 | 可以 | 缺少继续条件 |
| 第二轮重复假设 | 全部接受 | 缺少跨轮次假设身份与去重 |
| 两轮调度次数 | 10 + 10 | 即使材料不足也完整走四角色流程 |
| 三个审计都为 uncertain | 轮次仍为 completed | 流程完成与研究取得进展需要分开 |
| 事实条数 | 始终为 0 | 没有获得外部证据 |
| factRevision | 第一轮 9，第二轮 18 | 内部更新也会改版本，不能把它当作新增证据事件 |
| 重复录入同一来源、同一陈述 | 保留两条 | 不能按记录新增数计算信息增益 |

## 这个问题应该怎样推进

以下是设计演练，**不是实际用户实验，也不是本次模型输出**。

- 初始：整理“写问题促进回访”“邮件提醒才是原因”“操作负担抵消收益”等竞争假设；明确七日回访口径、最小有意义效果、采样与实验方案。先做一轮有预算的探索。
- 缺少数据：保存计划，进入“等待实验数据”。记录具体所需材料、负责人、预计检查时间与唤醒条件。其他有明确价值的资料检索或计算任务仍可继续，不能因为某个假设缺数据而冻结整个项目。
- 到达合成材料 E1：对照组 20/100 回访，干预组 30/100 回访，但仅干预组收到额外邮件。描述差异为 **10 个百分点**，相对差异 50%；样本不确定性和实验设计仍需核验。由于同时改变两项因素，不能将差异单独归因为“写问题”。
- 更新研究：在证据看板记录原始计数与提醒条件；单独记录“无法分离两项干预”的分析结论。只更新受影响的假设，下一步提出保持提醒一致的对照或因子实验。预先规定判定阈值，不根据结果事后改口径。
- 重复 E1：不唤醒研究团队，只更新来源检查时间；新网页转述同一实验也不能算独立证据。
- 没有 E2：保持等待。轻量检查材料是否到达，不重复生成长报告。

## 建议的开发顺序

### 第一批：探索控制与证据增量

统一新团队、旧节点循环与后台守护进程的继续/等待规则。当前旧节点流程已有现实验证触发器，新团队没有共用，守护进程又是另一套循环，不能只改一个按钮。

为每个问题保存：当前判断、开放假设、可执行下一步、继续理由、等待条件、预计成本、已消费证据事件。状态至少区分规划、执行、待证据、待人工、完成、失败。`completed` 仅表示该工作完成；进展另记“新增观察、推翻/修正判断、排除方向、提出可执行验证方案”。

唤醒事件包含新材料、实验结果、证据撤回或冲突、用户约束变化、到期复查。事件需要去重，记录影响了哪些假设与决策。增加预算、重复事件幂等处理、失败退避及运行锁。`factRevision` 保留为界面或记录修订版本，另设经过内容去重与相关性判断的证据事件，不直接混用。

没有外部证据也允许一次必要的假设设计、数学推导或实验规划，但必须有预期产出与停止条件。探索未知需要留出少量有预算的试探，不能把“没有新增外部证据”实现成绝对禁止思考。

### 第二批：真正获取证据与持续认知

优先接入一个能服务目标用户的证据通道，例如项目自身的产品事件统计、论文更新或实验结果文件。采集者保存原始材料、来源时间和内容指纹；验证者检查来源与适用范围；分析者更新判断。需要执行计算时接入可重现的代码运行与结果附件。现在新团队执行者只有模型文字推理，没有这些执行工具。

事实看板区分原始观察、来源已核验的记录、分析推断和暂定结论。来源可追溯不等于结论永远成立；保留样本、条件、不确定性、撤回与过期记录。严格规则可以自动核验格式和可重算结果，高影响或有冲突的结论仍交人工。不要把所有资料导入都永久卡在人工按钮上。

保留稳定的 hypothesisId、支持/反对证据 ID、结论适用条件和历史修改原因。长期记忆应检索旧的失败实验、已排除解释与未解问题，而不只是把最近两轮塞入提示词。现在事实提示有固定长度预算且顺序取记录，需加入相关性与更新优先级。

Work tree 阶段记录应包含“因何证据改变了何判断、接下来做什么”。将大附件单独按内容寻址保存，阶段引用版本；长期逐轮复制全文可能使本地存储持续膨胀。

### 第三批：调度角色与界面

保留思想家、执行者、验证者、审计者这些职责，按任务调用。先筛选最有价值的验证任务，不让每一个想法都固定走十几次模型调用。强审计优先用于结论改变、矛盾证据和高代价决策；执行失败或明显缺材料时直接转为等待。

仪表盘主要回答四件事：现在相信什么；最近什么证据改变了它；卡在哪里；下一次何时、因为什么启动。补充调用成本、有效更新和停止理由。笔记数、轮次数仍可展示，但不能代表研究质量。

## 模型怎么选

先恢复当前接入，建立相同资料、相同工具、相同预算的比较。用廉价模型做提取与候选去重，把困难假设设计、混杂识别和关键审计交给更强模型；这只是待验证的调度方案，不是已测出的最优组合。跨模型审核也不能替代独立证据。

评估集至少覆盖：无资料、重复资料、无关新资料、反证、过期资料、来源撤回、数学推导、完整实验、模型失败后恢复。记录正确引用、该等待时的停止情况、受影响判断更新是否完整、恢复是否重复调用，以及单次有效更新的耗时和费用。先完成这些评估，再决定具体升级型号。

设计参考：[Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) 强调环境反馈、停止条件和在评估基础上增加复杂度；[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) 讨论跨会话的增量工作与持久进度。本报告的具体优先级来自本仓库代码与上述流程测试。
